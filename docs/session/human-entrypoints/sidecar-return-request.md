# Sidecar Return Request

> **Artifact class:** Human entry-point template (non-canonical operator aid)  
> **Governing contract:** `docs/session/sidecar-bootstrap.md` and the original immutable Context Capsule  
> **Conflict rule:** The governing contract and Capsule override this template.

Fill the bracketed fields and send this request to the active Sidecar when you decide its bounded mission should end. The resulting typed Return is meant to be pasted directly into Mainline; no additional re-entry template is required.

## Authoritative routing

Read and apply:

1. the original immutable Context Capsule;
2. `docs/session/sidecar-bootstrap.md`;
3. only the work object, evidence, and artifacts authorized by that Capsule.

Do not load unrelated project context, create a new mission, update canonical state, or continue substantive work after beginning closure.

## Required Sidecar behavior

1. stop the active iteration and generate exactly one final typed Sidecar Return using the common schema and applicable role-specific fields in `docs/session/sidecar-bootstrap.md`;
2. verify whether the work stayed inside the Capsule's role, object, mission, scope, evidence, and read/write boundaries; disclose every deviation, unsupported source use, or unsupported attribution explicitly;
3. declare freshness only from provenance and changes actually known to the Sidecar; use `POSSIBLY STALE` or `STALE` when warranted and do not claim knowledge of unseen Mainline changes;
4. include the bounded direct result, preserved semantic boundaries, assumptions, uncertainties, verification, proposed Mainline action, and canonical-state impact;
5. list only real evidence/file references actually used; write `None` when there are none—never leave a placeholder or empty bullet;
6. include the required role appendix, but do not turn tutoring interaction, a rescue request, code execution, or workflow completion into unsupported learner-mastery, research-evidence, or implementation-progress claims;
7. compress to the minimum sufficient handoff: preserve conclusions, provenance, material evidence, failures, and unresolved items without reproducing the full Sidecar dialogue or large source artifacts.

Do not promote or write canonical state. Mainline must independently evaluate current acceptance compatibility and record `ACCEPT`, `PARTIAL ACCEPT`, `REJECT`, or `REISSUE`; a Return valid against its source Capsule is not automatically fresh against a materially changed Mainline task.
